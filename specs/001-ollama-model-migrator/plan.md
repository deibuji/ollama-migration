# Implementation Plan: Ollama Model Migration Tool

**Branch**: `001-ollama-model-migrator` | **Date**: 2026-05-01 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/001-ollama-model-migrator/spec.md`

## Summary

Create a Rust CLI application that extracts GGUF model files from Ollama's internal storage format and outputs them to standard GGUF files usable by vLLM, llama.cpp, and other LLM hosting tools. The tool operates as a zero-copy extraction (no re-quantization) from Ollama's content-addressable blob storage.

## Technical Context

**Language/Version**: Rust 1.75+  
**Primary Dependencies**: 
- `clap` v4.x (CLI argument parsing)

- `sha2` (Digest verification)
- `indicatif` (Progress bars)
- `anyhow` (Error handling)

**Constraints**: Streaming I/O required for large models (no full model in memory)  
**Scale/Scope**: Handle models up to 100GB+ (e.g., Mixtral 8x22B)

## Phase 0: Research

### Ollama Storage Format Research

Ollama stores models in a content-addressable storage system:

1. **Manifests Directory**: `~/.ollama/models/manifests/registry.ollama.ai/library/`
   - Contains JSON files named by tag (e.g., `latest`, `1.0`)
   - Manifest references blobs by digest

2. **Manifest JSON Structure**:
   ```json
   {
     "schemaVersion": 2,
     "mediaType": "application/vnd.docker.distribution.manifest.v2+json",
     "config": {
       "mediaType": "application/vnd.docker.container.image.v1+json",
       "digest": "sha256:abc123...",
       "size": 1234
     },
     "layers": [
       {
         "mediaType": "application/vnd.ollama.image.model",
         "digest": "sha256:def456...",
         "size": 9876543210
       }
     ]
   }
   ```

3. **Blobs Directory**: `~/.ollama/models/blobs/`
   - Files named by digest: `sha256-abc123...`
   - The model layer contains the raw GGUF data

4. **Key Finding**: Ollama stores GGUF files directly in blobs without modification. The migration is a pure extraction operation.

### Technology Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| File Copy | `std::fs::copy` + `std::io::copy` | Simple, portable, uses OS optimizations |
| Progress | `indicatif` | Standard Rust progress bar crate, minimal overhead |
| JSON Parsing | `serde_json` | Industry standard, zero-copy parsing possible |
| Error Handling | `anyhow` + `thiserror` | `anyhow` for app, `thiserror` for library |
| Parallel Exports | `rayon` | For batch operations (optional optimization) |

```rust
// Ollama model reference
pub struct OllamaModel {
    pub name: String,           // e.g., "llama3.2:latest"
    pub manifest_path: PathBuf,
    pub config_blob: BlobRef,
    pub model_blob: BlobRef,     // The GGUF data
    pub total_size: u64,
}

pub struct BlobRef {
    pub digest: String,          // sha256:abc123...
    pub size: u64,
    pub path: PathBuf,           // ~/.ollama/models/blobs/sha256-abc123...
}

// Export job
pub struct MigrationJob {
    pub source: OllamaModel,
    pub destination: PathBuf,
    pub status: JobStatus,
    pub progress: Arc<AtomicU64>,
}

pub enum JobStatus {
    Pending,
    Running,
    Completed { bytes_copied: u64, duration: Duration },
    Failed(String),
}
```

```
  -f, --format <FORMAT>      Output format [default: table] [possible values: table, json]

  -h, --help                 Print help
```
